## 我在意的工程习惯

**第一，先验证仪器，再相信仪器。**
Demo B 里我先测开源检测器的灵敏度，发现它在「评测腔 / 种草腔」语域上 20 条有 14 条判 0 分——
如果直接拿它当唯一指标，会得出「AI 味已降到 0，改善 100%」这种什么都没测出来的结论。
所以我改成**双仪器按语域分组并报**，不合并成一个总分。

**第二，数字不够好就按实测报。**
实测值达不到简历数值时，我在指标里注明差异原因，不做数字凑合。
上面表格里的每一个数，都能在仓库 `portal/measurements.json` 里找到对应的脚本与数据集。

**第三，自研和既有能力划清边界。**
仓库里有一张「组件来源表」：第三方开源、既有自研项目、本次新增，三分标注。
把别人的东西讲成自己写的，一被追问实现细节就会露。
