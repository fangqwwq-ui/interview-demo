# Demo C 讲稿：漫剧智能生产流水线（编排层）

> **口径（开场就要说清）**：这是**方案的独立复现 / 技术验证版**。
> **出图、配音、合成三项能力来自我既有的 `aigc-comic` 项目，我没有改动它一行代码**。
> 我做的是**编排层**：协议适配、提示词适配、审核层、指标埋点。
> 断点续跑是 `aigc-comic` 的既有能力，**不是自研**，我会明确区分。

---

## 一、开场一句话（30 秒版）

> 「漫剧生产流水线：剧本 → 分镜→ 出图 → 配音 → 合成 → 审核。
>
> 我的贡献是**在不改既有服务一行代码的前提下接入了它**——
> 它只认 A1111 的 API，我写了一个 shim 把A1111 协议翻译成 ComfyUI 工作流，
> 它就以为自己在跟 A1111 说话。接入成本是**改一个环境变量**。
>
> 另外我做了一件我认为更重要的事：**给流水线装了检测层**。
> 因为我最开始发现，扩提示词词表这个'优化'，真正起作用的是覆盖度，
> 而不是我想当然认为的'剥掉残留中文'。」

---

## 二、架构（含"我做的"与"既有的"边界）

```
剧本 ──> 分镜（既有服务）
            ↓
   ┌── 【我做的】提示词适配层 ──────────────┐
   │  中文 → Danbooru 词表（100 条）        │
   │  从问句/分镜抽结构化线索               │
   │  覆盖率可量化（按字符数）              │
   └──────────────────────────────┬────────┘
                                  ↓
      A1111 协议 ──>【我做的】A1111 shim ──> ComfyUI（出图）
                     (协议翻译层)                │
                                                ↓
   既有服务合成 MP4 ──> 【我做的】审核层 ──> 规则通道 (C1~C6)
                                                + LLM 通道（未接通）
                                  ↓
                    【我做的】指标埋点 + 口径登记
```

**必须主动划清的三条边界**（面试官最关心"哪部分是你做的"）：

| 部分 | 归属 |
|---|---|
| 分镜 / 出图 / 配音 / 合成 | **既有 `aigc-comic` 服务**，未改动 |
| **断点续跑**（任务状态机 + 断点恢复） | **既有能力**，我实测验证了它 |
| A1111 shim（协议翻译） | **我自研** |
| 提示词适配层（词表 + 覆盖率度量） | **我自研** |
| 审核层（规则 C1~C6 + LLM 通道框架） | **我自研**（既有服务无审核模块）|
| 指标埋点与口径登记 | **我自研** |

## 三、演示动线（建议 3 分钟）

### 第 1 步：先讲"零改动接入"（这是最漂亮的部分）

```bash
# 关键：只改环境变量，既有服务代码零改动
SD_API_URL=http://127.0.0.1:7860 python -m uvicorn demo_c_manju.a1111_shim:app
```

> 「`aigc-comic` 里写的是A1111 的调用方式，指向 `/sdapi/v1/txt2img`。
> 我没有去改它的代码，而是在前面加了一个 shim：
> 我实现 A1111 的 `/sdapi/v1/txt2img` 协议，把请求翻译成 ComfyUI 的工作流 JSON。
>
> 它以为自己在跟 A1111 说话，实际是 ComfyUI 在出图。
> **接入成本 = 一个环境变量。**」

shim 实现的端点（可现场展示）：
`/sdapi/v1/txt2img`、`/sdapi/v1/sd-models`、`/sdapi/v1/samplers`、`/sdapi/v1/options`、`/internal/health`

### 第 2 步：讲提示词适配的**真实结论**（这段最能体现严谨）

实测（用**既有服务的真实分镜提示词**，5 条，词表 100 条）：

| 指标 | 实测值 |
|---|---|
| 中文覆盖率（按字符数） | 均 **90.7%**（最低 81.0%，最高 97.1%）|
| 平均命中词条 | 10.4 条 |

**然后是这段必须说的话**：

> 「我原本以为'把残留中文剥掉'能提升画质，所以我做了单变量对照实验
> （`scripts/ab_prompt_adaptation.py`，同 seed 同尺寸）。
>
> 结论是：**扩词表让出图从'偏离分镜'变成'贴合分镜'，差异显著；
> 而在此基础上再剥离残留，肉眼无可辨识差异。**
>
> 也就是**真正起作用的是词表覆盖度，不是剥离**。
> 所以我现在的做法是：剥离只为了覆盖率可量化、少送噪声，
> **绝不声称它提升了画质**。」

> **这段的杀伤力**：主动推翻自己原本的假设，并用对照实验说话。
> 95% 的候选人不会承认自己的某个"优化"其实没用。

### 第 3 步：讲审核层（自研，且如实报命中情况）

```bash
python -m demo_c_manju.review
```

规则通道（C1~C6）实测：

| 通道 | 命中率 | 说明 |
|---|---|---|
| **注入层**（我故意造的 9 类缺陷）| **8/9（88.9%）** | 回归指标：证明规则抓得到自己设计的缺陷 |
| **真实层**（既有服务的真实分镜）| **0/3（0.0%）** | ⚠️ 场景意义有限 |
| 误报对照 | 0/1| 干净样本未被误判 |
| **LLM 通道** | **未执行** | 无 API Key / Ollama 未启动，**不给估算值** |

规则清单：C1 违禁词、C2 空行/过短行、C3 语法异常、C4 素材损坏（含路径穿越/绝对路径）、C5 提示词与分镜不一致、C6 占位图。

> ⚠️ **必须主动说**：
> 「88.9% 这个数字**只证明规则能抓到我自己设计的缺陷**，
> 它是回归测试，不是场景表现。
> 真实层 0/3 我不会拿它说事——**样本太少，且现有分镜本来就没什么问题**。
> 双通道互补量也**没测**，因为 LLM 通道不可用，我不编数字。」

## 四、可讲的工程决策

### 决策 1：断点续跑——我验证了它，但我没说它是我做的

实测：task `4b916255dbb3` 从 `audio_done` 状态恢复，**耗时 3.23 秒**，
0 个阶段重做，MP4 完整保留。

> 「这是既有服务的能力，我做的是**验证它真的有效**：
> 重新 POST 一次 `/run`，耗时 3.23 秒 vs 全新跑 67 秒。
>
> 但这是**它的能力，不是我的**。我在文档里明确标注了归属。」

> **强调「不抢功」的价值**：面试官见过太多把既有工作说成自己做的例子。
> 主动划清边界反而更可信。

### 决策 2：指标必须能追溯到脚本

> 「项目里所有数字**只能由脚本回填**，不许在文档里手写。
> 因为我被这个坑坑过：内存里刚测出的数据，被另一个进程重新导出覆盖了，
> 数字就消失了。现在是 `registry.set_measured()` →持久化 →
> `export_json()` 合并，三步固定顺序。」

### 决策 3：不引入 LangChain 之类的大依赖

> 「三个 Demo 都没有引大框架。原因是**降级路径必须始终可跑**——
> 演示现场不保证能临时装包（我本机带宽只有 343 KB/s，装一次 torch 要 137 分钟）。
> 所以每个外部依赖都有降级实现，且降级时`is_fallback` 如实上报，
> 指标页会标出实际用的是哪个后端。」

## 五、踩过的坑（挑 2 个）

### 坑 1：第三方项目被沙箱守卫打断（不是代码 bug）

> 「`aigc-comic` 跑着跑着返回 HTTP 500，但状态文件显示 `audio_done`——
> 脚本、出图、配音都成功了，只有合成步消失。
>
> 查下来是我的**环境**问题：它合成完要清理临时文件（`unlink`），
> 而沙箱的批量删除保护把清理拦了，抛的是 `SystemExit` 而不是 `OSError`——
> 它的 `except OSError` 接不住，整个请求就500 了。
>
> 我**没有改它的源码绕过**（那是既有项目），而是换到普通终端跑。
>
> 这件事我想说的是：**报错信息会误导人**。`status=audio_done` 会让你以为
> 合成没跑，实际上 MP4 早就写好了。」

### 坑 2：自己造的测试样本掩盖了真实缺陷

> 「我最初用**自己编的测试提示词**验证词表适配，覆盖率 100%。
> 换成既有服务的真实分镜提示词——只有 4~5 个词命中。
>
> 于是我把词表从 53 条扩到 100 条，加了年龄正则，修复了替换后粘连成
> `universityclassroom` 这种伪词的问题，覆盖率才到 90.7%。
>
> 结论：**跑通 ≠ 可用。验证适配层，输入必须来自对方，不能自己造。**」

## 六、主动交代的局限

| 局限 | 说明 |
|---|---|
| **只实测了出图阶段** | 流水线 4 个阶段我只覆盖了阶段 1（出图）|
| **效率提升 160% 不成立** | 我只报绝对耗时（稳态 14.463s/张，n=3）。倍数需要人工基线，而人工基线是**申报假设（54 分钟/条）非实测**，所以不引用倍数 |
| **LLM 审核通道未执行** | 无 API Key / Ollama 未启动，**双通道互补量不给估算值** |
| 真实层审核样本太少 | 3 条，不足以说明场景表现 |
| 提示词覆盖率只管"转走"不管"转对" | 无图文对齐模型，**不构造语义评分** |
| 依赖既有服务 | `aigc-comic` 不可用则本Demo 不可用 |

## 七、可能的追问 → 见 `docs/objections.md`

1. shim 是不是就是个反向代理？→ 协议翻译 + 工作流 JSON 生成，含采样器/尺寸映射
2. 为什么不直接改既有代码？→ 归属边界；且既有服务有它的稳定性考虑
3. 审核层 88.9% 是不是自己出题自己考？→ **是**，所以我同时报了真实层 0/3
4. 断点续跑听起来是既有能力，你的增量在哪？→ 在**接入 + 验证 + 指标口径**，不在这项本身
